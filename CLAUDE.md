# vovk monorepo

Workspaces: `packages/vovk` (runtime), `packages/vovk-cli`, `packages/vovk-ajv`, `packages/vovk-python`, `packages/vovk-rust`. `test/` is a separate Next.js app with its own lockfile that consumes all packages and holds the integration tests. Docs live in the separate vovk.dev repo; `skills/` holds the in-repo task guides.

## Commands

- `npm run build` builds all packages (turbo)
- `npm t` runs everything: lint (biome), build, unit and integration suites, CLI specs
- `npm run test:main` generates the client, typechecks and runs the test app suites

## Conventions

- Conventional commits: `fix(scope): subject`. Git tags are per package: `vovk-v3.7.0`, `vovk-cli-v0.2.0`.
- Each package ships its `CHANGELOG.md` in the tarball; it is the only changelog, GitHub Releases are not used. Entries are noteworthy changes only, one short line each, linked to the PR or commit. They are written on request when preparing a release, not per commit and not by tooling; do not add entries unprompted.
- Generated files start with the `Generated by vovk-cli` first-line banner (`packages/vovk-cli/src/utils/generated-banner.mts`). The pruner keys on it, so every new non-JSON template must emit it on line 1.

## Hard rules

- Never run `npm publish` or any publish script (`patch`, `minor`, `beta`, `BREAKING-*`, `draft*`, `vpub*`); publishing is manual. `NOTEST=IAMSURE` skips the pre-publish test run.
- Never edit `version` fields or the published packages' peer ranges; stale in-repo versions are expected between publishes.
- Lockfiles: plain `npm install` only, never `--legacy-peer-deps` (it strips next's peer react entries from the root lockfile and breaks `npm ci`). After dependency changes verify with `npm ci --dry-run` on npm 10 and npm 11, at the root and in `test/`.
